# 最后一题：我怎么用 AI

## (a) 最近一次完整交付，以及我和 AI 各做了什么

在这套笔试之前，最近比较完整的一次，是 RealRoute-Bench 的高德 API 数据采样。我让 AI 帮我规划请求额度、处理代理和网络稳定性、编写并执行采样程序，再检查采样结果有没有缺失、超时，以及数据是否完整合理。

我主要负责说明要采什么、采样的目标和约束，决定哪些结果能接受，遇到问题后调整方案。AI 负责把这些要求落实成脚本，执行请求、整理数据和检查结果。我能交付的是这部分采样流程和数据，不代表整个 benchmark 的基线和排行榜都已经完成。

使用过程中，我发现 AI 有时不会一直记住我的指令，还会在没有充分检查的情况下说任务已经完成。这也衍生出了 Agent Replay：我给出思路、预期功能和设计约定，让 AI 辅助实现记录、回放和检查，并另开审查 Agent 核对实现和测评。我关心的是它到底做过什么、结果能不能查，而不只是最后给我一句“完成了”。

另外我也尝试过用 AI 做推广视频。我提供素材，以及视觉元素、转场、动态效果、拟人化处理和视觉中心等要求，AI 帮我把这些想法做成视频。这类工作里，我还是需要把想要的效果讲具体，再根据实际结果调整。

## (b) 那次 AI 有没有跑偏，我怎么发现

有。在之前的项目实践中，我发现 AI 有时会漏掉前面约定的要求，或者只做了一部分，就告诉我整个任务已经完成。这也是我后来想做 Agent Replay 的原因。

我的检查方式是把最初的要求和实际结果对照起来看。比如采样任务，我关心的不只是脚本有没有跑完，还包括请求有没有超时、数据有没有缺失、结果是否完整合理。AI 说完成了，我还需要看请求记录、实际数据和检查结果，确认这些能不能支持它的结论。

在 Agent Replay 的开发中，我会给出预期功能和验收要求，再另开审查 Agent 检查实现和测评。审查 Agent 也可能判断错，所以我仍然要求它说明依据，回到代码、日志和测试结果上核对。对我来说，发现问题的关键是能看到它做过什么，并且和原来的要求对得上。

## (c) 我有没有写过规则文件

有，但没有系统地整理过，主要就是下面这些要求：

```text
- 先勘察再下结论：优先确认真实代码入口、配置入口、测试入口和运行链路。
- 少说空话，避免把猜测包装成事实。
- 代码结论尽量附上入口文件、验证命令或关键路径。
```

加这些，是因为我发现 AI 有时还没弄清项目就开始下结论，或者说做完了，却没有给出足够的依据。我希望它先看实际代码，再说明判断从哪里来，方便我核对。

## (d) 用量、模型和怎么控制消耗

按我自己的观察，做这套题大约用了 ChatGPT Plus 当周额度的 30%。这只是额度变化的粗估，不是精确的 token 统计。我没有把网页端、Codex 和 Cindy 等工具的用量统一汇总，所以目前不能给出准确的总 token 或总费用，也不能把这个比例直接换算成多少钱。

主要使用的是 GPT-6.1 Sol，推理强度一般选 medium。这次也用了 Cindy 制作插件；B2 的跨 Agent 验证实际调用了 Codex CLI 和 Claude Code，其中 Claude Code 的回执模型是 DeepSeek，不能写成验证了 Claude 模型。具体实现、检索、测试和材料整理都有 AI 参与。

控制用量上，我一般先在网页端规划方案，另开一个 AI 审查方案是否合理、指出 raw 初稿的漏洞，再回到自己的笔记里修改。交给执行 AI 时，尽量一次说清目标、工作目录、约束、交付内容和验收方法，让它先读相关规则和入口，不要一上来就把整个仓库都读一遍。

遇到问题时，尽量围绕具体报错和实际改动继续排查，已经确认、没有受影响的内容不反复做。每一轮保留简短结论和关键路径，也能减少重新讲背景的消耗。不过另开审查和多轮验证本身也会增加用量，这次有些验证做得比较细，我还需要继续改进什么时候值得加一轮检查的判断。

## (e) 哪道题我还不太确定

我最不确定的是 A2。我对 Cindy 或类似产品的完整发布链路了解还不够，也缺少实际参与线上发布和排障的经验，需要 AI 帮我补充链路，再自己沿着每个节点分析报告哪里推理不成立。

比如，服务端文件已经有 46 条，不代表生产接口已经返回 46 条；客户端本地只有 45 条，也不能直接证明它收到新配置后丢弃了。这个逻辑我能理解，但具体项目里还有部署、CDN、客户端校验、覆盖和可见性等环节，哪些环节真实存在、这次走到了哪里，都需要继续核对，不能照着 AI 画的流程就认定是事实。

另一个不确定的是 B2 能不能在不同 Agent 上一直稳定执行。两轮共 8 个独立会话的测试已经说明，它能辅助完成收尾，但只靠文本约定还不能保证每一步都照做。目前验证了 Codex CLI 和配置 DeepSeek 的 Claude Code，Pi 没有测。我会保留这个限制，后续再考虑用脚本约束事实记录，继续验证，而不是把“已经写出 Skill”当成“已经彻底解决”。

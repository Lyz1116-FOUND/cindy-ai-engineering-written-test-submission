# B2 跨 Agent 实际执行验证

日期：2026-10-30（Asia/Tokyo）。本次实际调用两个 CLI，各执行两个隔离样例，共四轮。结论：**结果判断与不修改文件的约束均得到验证，但严格顺序和扫描边界未全部符合，不能宣称跨 Agent 一致通过。**

## 执行对象与方式

- Codex CLI：`0.165.0-alpha.1.2`，使用当前配置，`exec --ephemeral --sandbox read-only --json`。回执未暴露实际模型型号，不据此推断。
- Claude Code：`2.1.304`，实际配置模型为 **DeepSeek-flash[1m]**，不是 Claude 模型；使用 safe mode、非交互调用及只读/本地测试工具白名单，不提供编辑工具。部分复合命令被权限系统拒绝，随后改用允许的简单命令完成。
- Pi：PATH 中未找到可执行文件，未安装、未执行，不能写三种 Agent 都已验证。

四轮都显式要求读取同一份 SKILL.md 并执行“收工”，提供明确基线和范围。没有给 Agent 预期结论或修复建议。验证的是正文在真实工具链中的执行，不是 Skill 自动发现、安装目录、斜杠命令或自然触发的验收。

各轮使用独立临时 Git 仓库，不含业务凭证、真实项目数据或外部依赖。测试为 Node 内置测试，经项目规定的 `npm test` 运行。未修改实际业务仓库。两个 CLI 的隔离配置不同，且 Codex 保留自身配置，因此这不是控制所有变量的模型能力比较。

## 发现的偏差

1. **Claude Code 两轮都先完整审阅，再跑测试。**正常轮工具序号 13 请求三段完整 diff，序号 14～16 才尝试测试；故障轮序号 5 已请求完整 diff，序号 13～14 才测试。读取配置和文件名属于定范围，但读取全量 hunk 已超过这一准备动作。最终回答字段齐全不能抵消顺序违规。
2. **Claude Code 故障轮扩大扫描范围。**它对整个样例仓库做 Grep，并把本次未修改的 AGENTS.md 里提及 console.log 的文字列为合法命中。没有误删，但违反只扫描本次变化的边界。
3. **两种回答的解释不完全相同。**Claude 对 CLI 新增的 `[--help]` 提示提出需确认项；Codex 未将其列为问题。这是允许保留的语义判断差异，不能将“每次一样”理解为逐字相同。

本次没有为得到通过结果而调整 Skill 或重新提示 Agent。上述两项执行偏差保留为未解决问题：若要求严格顺序与扫描边界在所有宿主上可靠执行，需要进一步收紧阶段门禁或引入可核验的执行编排，并重新验收。本次记录不能证明这些问题已修复。

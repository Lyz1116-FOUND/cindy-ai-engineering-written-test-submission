## 设计选择

题目要求的固定顺序是测试、完整审阅、排查临时调试残留、简短总结。增加的准备阶段只解决“在哪个项目、检查哪次改动、使用什么测试命令”，不改变四步顺序。

主要补足五个容易产生假完成的缺口：

1. 只看 git diff 会遗漏已提交内容和新增未跟踪文件，因此先确定起点与文件清单。
2. 测试启动、历史通过和本轮通过不同；命令缺失或失败不能写成成功。
3. 关键词命中不等于临时残留，正式日志、测试夹具和默认值需要结合上下文判断。
4. 修正残留会改变被测试代码，因此只重跑受影响测试，并重新检查新增差异。
5. “收工”要求检查与报告，不自行扩大为 Git 提交、推送或发布。

## 纸面场景检查

以下是对规则的逐项推演，未调用另一个 Agent 做真实执行测试：

| 场景 | Skill 要求的行为 |
| --- | --- |
| 分支已有提交，另有暂存与未暂存文件 | 按已确认基准检查分支范围，同时审阅暂存、工作区和新增文件。 |
| 测试失败或依赖缺失 | 记录原因，继续能做的审阅与残留检查；最终说明尚未完成。 |
| 正式日志和测试中出现固定值 | 阅读上下文，不批量删掉合法代码。 |
| 删除了明确的临时调试语句 | 更新文件清单，重跑受影响测试，复核新增差异。 |
| 找不到可靠的本次起点 | 限定已确认范围；必要时询问起点，不能宣称完整收尾。 |
| 测试过程中生成了新文件 | 最后状态复核时识别并判断用途，不能漏看或自动删掉用户文件。 |
